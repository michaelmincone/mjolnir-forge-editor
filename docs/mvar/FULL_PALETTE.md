# Full Forge World palette amendment

This amendment extends the frozen original `SPEC-mvar.md` without changing its
API contract. Local filesystem references in the specification were rebased on
2026-10-21; its technical decisions and recorded results remain historical. Added on 2026-10-19 for the user's full
348-object support goal.

## Native evidence

`mvarlib/data/object_support.json` records 348 names and numeric defaults from the
installed stock Forge World scenario and its referenced multiplayer objects.
No meshes, bitmaps or executable bytes are included. The document records hashes
of the source cache, DLL and layout schemas. Other maps and unrecognized palette
revisions do not inherit Forge World's creation metadata.

The original library tree continues to describe 194 preview collections. The
separate object browser adds every missing stock name in its native category.
Objects without a model in the chosen library remain marked editor objects.
The separately generated full library contains 348 modeled collections: native
physical geometry and meaningful editor representations for markers and volumes.
Its 411 images are packed. The original library is preserved byte for byte.
Materials approximate static game shading; animation, particles, reactive shields,
screen filters and physics are not simulated. Existing invisible-block helper
boxes are approximate editor geometry, not authoritative collision bounds.

For a new object, an unambiguous template class keeps precedence unless the object
explicitly requests its matching verified native class. If unavailable,
the native definition supplies the class for a corroborated Forge World palette.
Existing imported slots retain their exact class, extras and unchanged bit fields.

Fresh Blender objects request their verified native class, which exposes controls
such as spare clips even when a legacy template stores class-zero weapons. An
imported class-zero object can explicitly enable its matching verified native
settings; this rebuilds only its class-specific payload and keeps its placement
and other objects unchanged. Arbitrary class changes and uncorroborated palettes
remain refused. Imported objects are never upgraded implicitly.

## Complete palette and named locations

REA/Ghidra inspection of the pinned DLL confirms these procedures:

- `0x18006c710` sums scenario entry counts.
- `0x18006bd5c` computes the palette hash from category, entry and variant counts.
  Its unsigned-32 transcription reproduces both shipped controls: 89 entries gives
  `0x20E1C0E1`, and 144 entries gives `0x3715E608`. The installed 145-entry palette
  gives `0x8B33E8AC`.
- `0x18006f7f0` writes class 19's location-name index as eight-bit index-plus-one;
  `0x18006fa9c` reads eight bits and subtracts one. There is no optional flag bit
  in this native class-19 branch. Zero stores the `-1` sentinel; the maximum index
  is 254. Fresh evidence ID:
  `ev_537fb1f10b74f207b94e680ed04855491a4c64368f7f7c2130e80dbbd5ec0483`.

When a new or retargeted stock type needs a missing entry, a corroborated legacy
template is extended to the complete native 145-entry quota table, with native
maxima on appended rows and the complete palette hash. The template on disk is
never changed. The planned fixed header, quotas and all object requests are
verified by re-reading the generated bytes. A no-change export remains byte exact.

The complete native palette selects the established `plain8` location-name codec
when no diagnostic filter was supplied. Legacy files retain layout discovery,
including support for the previously researched alternate layout.

Modified corroborated variants recompute their spent-budget word from native
prices, while a no-change export remains byte exact. A complete-palette extension
also uses the installed scenario's native maximum budget of 30,000. Unrecognized
prices leave the original budget word unchanged and retain the original budget
note. Over-budget files are reported rather than silently enforcing a new loading
limit; repeated-stock-object behavior is a separate, runtime-dependent workflow.

## Native 3D orientations

The corroborated Forge World palettes use the pinned native cube-face up encoding
and orientation basis for both reading and writing. `0x1800dbff4` selects
`normalize(Y cross up)` when `abs(up.y) <= abs(up.x)`, otherwise
`normalize(up cross X)`, then forms the second axis from `up cross reference`.
`0x180070bd8` packs the dominant-axis face (ties prefer Z, then Y), tangent cell
step `float32(2/416)`, 417 row stride and 174762 face stride. The angle writer
`0x1800706e8` uses the decoded stored up vector and a 14-bit angle. Disassembly
and fresh REA/Ghidra evidence:
`ev_db4a03b3025ddcdba9ede1960ab7d8c665bc5ed31c50f1c6dadb5d6c969fc6d8`.

Changed/new 3D rotations retain the existing explicit rotation-export option.
Other, uncorroborated palettes keep their original conservative behavior. Native
rotations are checked within their quantization resolution; a no-change export
preserves original slot bits exactly.

Old Blender projects may contain the previous display-only orientation guess.
An unchanged rotation with a matching imported slot token resolves from the
embedded source, preserving no-op and move-only exports. Refresh Object Previews
can correct that untouched display orientation while preserving the actual game
placement. User-changed rotations remain user changes.

Offline file, browser and property checks do not establish Xbox loading, editing,
resaving, physics or gameplay behavior. Native model preview completion is tracked
separately from serializer support.
