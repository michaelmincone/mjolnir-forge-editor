## Decisions (most reasonable choice made, work continued)

1. **Nested Add submenus use a pool of 48 pre-declared `Menu` classes** (`VIEW3D_MT_add_forge_object_00..47`). A `Menu` takes no argument, the old code passed the node with `context_pointer_set` of a real Collection, which a static JSON tree does not have, and registering classes from the tree inside `register()` would read a file there. Each pooled class draws the group with the same number (preorder, root excluded) of the cached tree; the 23 groups use 23 of the 48; a larger tree is drawn inline (never an error). Groups without a visible leaf for the map are not shown.
2. **Extra object custom props** beyond SPEC 8.3: `mj_physics` (raw 2-bit physics, so the unused value 2 is handed back unchanged until the enum is edited: 8.7 #7 and B-21), `mj_helper` (`'shape'` / `'camera'` on helper children: found by parent link, deleted on replace), `mj_type_name` (the display name chosen in Add > Forge Object when the library has no model: without it a model-less new object has no type at all). `forge.objectType` defaults to -1 (it was 0, which exported an Assault Rifle: 8.7 #12) and `type_id_hint` is that value.
3. **`E_OBJ_NO_TYPE` only for objects that did not come from the file** (no `mj_slot`). An imported object whose record has no type id (`type_id` -1) is left to the library (tier 1, 7.4), so a no-op export of such a slot is not refused by the glue.
4. **Unevaluated objects get their transform rebuilt.** Probed on 5.2.1: after a Python edit, `matrix_world` stays stale (0) for `hide_viewport` objects and for objects only in excluded collections (the depsgraph does not evaluate them), but is right for `hide_set`. Pass A therefore uses `matrix_world` where the object and its parents are evaluated and `matrix_parent_inverse @ matrix_basis` up the parent chain otherwise (`mjolnir.world_matrix`). `hidden` is true for eye-hidden, `hide_viewport` and excluded-collection objects; `W_HIDDEN_EXPORTED` counts all three.
5. **Glue-level problems do not stop the library from being asked.** `E_MIRRORED`, `E_OBJ_NO_TYPE`, `E_ARRAY_NOT_EVALUATED` are collected; the library is still called (an unevaluated array source is handed over as a plain object so its slot stays claimed) so that one report lists every problem; the export is refused when any error exists, whatever `ok` says. Early refusals that make the call pointless (`E_NO_TEMPLATE`, `E_TEMPLATE_CORRUPT`, path policy, no target) return before objects are collected, as 8.5 steps 1 and 2 say.
6. **Extra glue issue codes** (not in the 7.3 table): `E_NO_TARGET` ("No output file was chosen.") and `E_INTERNAL` (an unexpected exception inside the library call, an `ok=False` result without errors, no data, or data that cannot be read back).
7. **Read-back check before writing**: for a changed result the glue re-parses `result.data` through `P.load_map_variant` and refuses on any exception (the frozen `api.write_atomic` has no verify hook, D8-5). A passthrough (`data == template`) is not re-parsed.
8. **The export list is sorted** (claimed objects by slot then name, new objects by name) so unlinking, relinking or moving to another collection (depsgraph order) hands the provider the same list (B-09). Array instance k of source S is named `"<S> [000k]"` (instance 0 keeps the source name, slot and token).
9. **`AddonPreferences`** (`bl_idname = __package__`): `library_path` and an extra `protected_folders` string (`;`-separated; checked in addition to the built-in folders because the provider has no way to extend `protected=None`). Library lookup: preference, then `$MJOLNIR_LIBRARY`, then `<package>/Resources/Halo Reach.blend` (dev loop only). A value naming a folder gets `Halo Reach.blend` appended. The tests always set `$MJOLNIR_LIBRARY` (stand-in, `--real-library`, or a nonexistent path) so the dev loop never touches the real file by accident.
10. **Physics value 2** shows as NORMAL; **team none** shows as NEUTRAL and is exported as 8; colour -1 is `TEAM_COLOR` (the library treats both as unchanged, 6.4).
11. **Setup Array** keeps `forge.py`'s behaviour: the array offset is expressed in the source object's own frame (imported objects facing +X therefore step along world -Y); documented in B-11. `ScaleObjects` keeps the positional `bpy.ops.transform.resize` (it moves the selection about the pivot while the locked scales stay at the sequence scale) inside a `try/except` that downgrades a failure to a WARNING.
12. **`ForgeCollectionProps.icon` stays** (editable on local collections, listed once with a module-level items list) but the Add menu no longer reads it: icons come from `palette.GROUP_ICONS`, checked against the running Blender's icon enum by B-04.
13. **Export report** always goes to the text datablock `Mjolnir Export Report` and the console, also for early refusals. It prints every `Issue` with its code, one line per `DiffEntry`, the stats (objects before / after, bits used of 229,376, L, hash flavour, then every key), and adds the 5.8 budget and "never checked against MCC" notes only when the library did not return `I_BUDGET` / `I_UNVERIFIED` itself (`I_PALETTE` needs the CRC and is left to the library). The summary line is the spec text; a trailing " N edited." is added when `edited` / `retargeted` entries exist.
14. **Replace confirmation**: `invoke` asks `invoke_confirm` only when a path is already preset (drag and drop) and a map variant is in the scene; with no path the file browser opens and the "Replace Existing" checkbox is visible there. Several dropped files: the first is imported and a WARNING says so.
15. **Export `invoke`** refuses at once (ERROR, no dialog) when the scene has no template.
16. **Bytecode**: the tests set `sys.dont_write_bytecode` (Blender's Python ignores `PYTHONDONTWRITEBYTECODE`), so `tests/blender/` gets no `__pycache__`. The `--dev` loop still writes `Addon/__pycache__` (ignored by `.gitignore`).
17. **G0 test files edited** (the only edits outside the G4 file set, forced by the tree no longer being empty, SPEC 11 G0 says the tree "is the valid empty tree" only until G4): `tests/unit/test_tables.py` (`test_palette_tree_is_the_empty_tree_in_g0` replaced by `test_palette_tree_is_the_generated_tree_and_a_copy`: 194 unique leaves, a copy is returned), `tests/unit/test_api_surface.py` and `tests/unit/test_provider_stub.py` (the assertion `palette_tree() == {"groups": []}` became `== tables.palette_tree()`). The committed tree keeps the G0 convention (`groups` / `leaves` / `name`) plus `schema` and `source`.

## Spec defects and gaps found (section numbers)

1. **8.5 pass A, "Transform from `ob.matrix_world`"**: stale for `hide_viewport` and excluded-collection objects (probed, decision 4). A move made while such an object is hidden would otherwise be exported at its old position.
2. **8.6 / 8.8, nested Add submenus**: a `Menu` cannot receive a tree node and the spec's `context_pointer_set('forgeColl', ...)` needs real collections; the spec does not say how submenus are drawn from the static JSON (decision 1).
3. **9.4 / 8.2, `--addons` and preferences**: an add-on enabled by `--addons` is not in `bpy.context.preferences.addons`, so its `AddonPreferences` are unreachable in the headless run (the glue falls back to `$MJOLNIR_LIBRARY`). G6's B-20 ("the stand-in library path in the preference") must call `addon_utils.enable(name, default_set=True, persistent=True)` first; probed: after that `bpy.context.preferences.addons[name].preferences.library_path` works.
4. **9.4 B-01 "handlers removed"**: nothing in 8.2 says whether the relink handler counts; here `load_post._on_load` is the only handler (plus `depsgraph_update_post` outside background mode) and both are removed on unregister.
5. **8.7 #10 / B-10** do not say what an eye-hidden array parent does: it behaves like `hide_viewport` (no evaluated instance, `E_ARRAY_NOT_EVALUATED`), probed.
6. **8.4 step 3** deletes objects "with `mj_slot`" which includes Shift+D duplicates of imported objects (they inherit the property); that is intended here but worth stating in the user documentation (G7).
7. **7.3 table**: no code for "no output file chosen" or an unexpected library exception (decision 6).
8. **11 G4 "B-08 (display + refusal passthrough)"** and **9.4 B-08** speak of `E_FLAG_UNVERIFIED` raised by the library; the glue test can only pass the changed value and show an injected refusal (the real refusal is G5/G6).
9. **9.4 B-03**: "driver_namespace holds no key starting with `mjolnir` ..." is checked in both processes; a fresh Blender 5.2.1 holds other entries, as stated.
10. **9.2 `--python-exit-code`**: a `sys.exit(1)` in the driver script gives exit status 1 (used by `run_all.py` and the stand-alone test files).

## Notes for G5 / G6 / G7

* The glue builds `ExportObject` with: `name` (array instance k>0: `"<source> [000k]"`), `slot`/`token_*` only for objects that carry them (array instance 0 only), `name_matches_import = (name == mj_name)`, `type_name` (palette collection `.name` minus `.NNN`, else `mj_type_name`, else ''), `type_id_hint = forge.objectType` (-1 if never imported), `position/forward/up` from the matrix (columns 3, 1, 2; forward and up normalised), `physics` 0/1/3 (the raw imported value while the enum is unchanged), `symmetry` 0..3, `team` 0..8 (NEUTRAL 8), `color` -1..8, `label_index` -1 or the file index, `hidden`, `from_array`. `ExportOptions.imported_slots` is `scene['mjolnir']['imported_slots']` (a failed slot is never in it).
* For G6: the `--provider real` variants should reuse `bl_common` (`Env`, `FakeUI`, `record_vs_export`) and `tests/blender/make_standin_library.py`; `Env.import_stub` / `export_to` are provider-agnostic apart from the stub controls. The glue never calls `P.load_map_variant` after an export of an unchanged template.
* For G7: user-facing facts to document: Replace Existing, the report text, `Library path` preference / `$MJOLNIR_LIBRARY`, the extra protected folders preference, Duplicate-of-imported = same slot (the library keeps the object whose name still matches), arrays count as N objects, hidden objects are exported (delete them to remove them), `Allow unverified rotation export` also gates new objects.
