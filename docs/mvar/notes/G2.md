## 2. API for G3, G5, G6 (and the Blender tests)

```python
import helpers_fixtures as hf                    # tests/unit/helpers_fixtures.py (tests/unit is on sys.path in run_tests.py)
build, selfcheck = hf.modules()
spec  = build.load_spec("w1_minimal")            # the committed JSON
built = build.build(spec)                        # built.data (bytes), built.sha256, built.info, built.model
model = build.normalise(spec)                    # "declared" values: every default filled in, generators expanded (alias: build.declared)
data  = hf.fixture_bytes("w1_minimal")           # bytes in memory
path  = hf.fixture_path("w1_minimal")            # file in the temp fixtures dir (MJOLNIR_FIXTURES_DIR)
build.spec_names()                               # all 49 names
```
Blender tests can instead put `tests/` on `sys.path` and `import fixturebuilder`.

* `built.info`: `file_length`, `size`, `end_bit`, `L`, `stored_hash`, `axis_bits`, `header_end`, `sections` (`header, body_fixed, labels, guid, slots, quotas, end` as bit offsets),
  `slot_ranges` ({slot: (start, end)}), `slot_field_spans` ({slot: [(field, start, end), ...]}, field names as in SPEC 3.6 with `parent`, `team`, `extras`),
  `free_bits`, `eof_offset`, `type19_status`.
* `built.model`: the declared values. `model["slots"]` is `{index: slot}` with the raw ints of SPEC 5.1 (`folder`/`item`/`label`/`color` are `None` when the absent bit is set;
  `pos` list of 3 cells; `up_global`/`up_code`; `dims`; `spawn_seq` signed; `extra`: see section 4); `labels` (`offsets`, `buffer`, `texts`, `compressed`, `comp`),
  `quotas` (list of `[min, max, placed]`), `header`, `body`, `guid` (bytes or None), `layout` (`axis_bits`, `type19`).
* Every spec carries `expect` (derived from the bytes by the independent walker, verified against the builder in U-20): for positives `shape`, `file_length`, `size`, `flavour`
  `{length_endian, recipe}`, `length`, `length_class`, `eof_endian`, `header_end`, `end_bit`, `sections`, `slot_ranges`, `present_slots`, `label_texts`, `hypothesis` (the one a reader
  must select), `type19_status`, `guid_contradicts_version`, `accepted_hypotheses`, `hypotheses` (all of them with `accepted` and the first `reject` reason), `read_warnings`, `stored_hash`,
  `free_bits`; for negatives `outcome: "error"`, `error` (the exception class of SPEC 6.2 / 7.2), `message_hint` (the **walker's** wording, not the library's) and the per-hypothesis table.
  `read_warnings` lists only warnings the spec clearly implies at read time (`W_ZERO_RANGE_AXIS`, `W_GUID_VERSION_MISMATCH`).
* `selfcheck.read(data)` is a complete reference reader (outcome dict); `selfcheck.expand_cmp(data)` derives the DEC-2.6 expanded form of a `cmp4` / `cmp4+fsm` file.
* `design.must_reject` (some specs): hypotheses the fixture was built to reject, verified with all checks and with the two unsourced checks of 3.10 rule 3 (`label entry present`, `folder < quota_count`) switched off.

## 4. Representation choices G3 must know

* `extra` of a slot: type 1 `[clips]`; types 12, 13, 14 `[channel, flags]`; **type 19 under `flag8`: `[flag, index]` (flag 1 = none, index 0); under `plain8`: `[stored]` (stored = index + 1, 0 = none)**; others `[]`.
* Axis hypotheses: 2 range computations (double difference of the float32 bounds, float32 of that) x 3 variants, **distinct triples** (as 4.1); hypothesis order for the tables: GUID value implied by the version first, then `flag8`, `plain8`, then triples in first-seen order.
* `hypotheses[].reject` values: `oob`, `length`, `parent`, `folder`, `label`, `upface`, `overrun`, `bounds`, `quota_count`, `labels`. `folder` and `label` are the two checks of 3.10 rule 3 that the spec itself marks as unsourced.
* Message wording in `message_hint` is mine; only the exception class is a requirement.

## 5. Decisions taken (most reasonable choice; the owner was not asked)

1. **Extra files.** `tests/fixturebuilder/catalogue.py` (the spec list is data, kept apart from the builder) and `tests/unit/helpers_fixtures.py` (shared loader) are not in the G2 deliverable list; `build.py` re-exports nothing, the catalogue is used by `--write-specs/--check`.
   Extra fixtures beyond the list: `w1_E1 w1_E2 w1_E2b w1_E3`, `cmp_expanded cmp_fsm_expanded` (listed as "golden expanded files"), `axes_16_17_18 axes_19_20_21 axes_22_23_22`, `axis_threshold_f32`, `length_capacity`.
2. **`_cmp` fixtures use a stored (uncompressed) deflate stream** in a valid zlib wrapper (`78 01`, one stored block, Adler-32), so the file bytes are identical under every zlib version and there is no circularity between the compressed length and the fileLength field. The wrapper header is version 1, flags 1 (not specified anywhere), type byte 0, then the u32 BE size 0x7028.
3. **`labels_compressed` uses a frozen real zlib level-9 stream** (a literal in `catalogue.py`; Python's zlib 1.2.12 and 1.3.1 produce the same 125 bytes), so builds never depend on the local zlib.
4. **fileLength inside a `_cmp` file** (SPEC 2.8 says it is `U`): the stream's embedded field, the chdr field and the `_eof` value all hold the real length of the `_cmp` file through `_eof` (29,509), so expanding to the plain form (29,481) really exercises the re-stamp. The expanded golden has 29,481 everywhere and a recomputed hash.
5. **`_fsm` block** = total size 0x1C4 (452) including the 12-byte header, body 440 deterministic bytes (SHA-256 chain of a seed); the same block is used verbatim in `cmp_fsm_expanded`.
6. **`trailer`** = 512 zero bytes.
7. **`near_full`** uses a label buffer of 8006 bytes (13-bit size field; RVT's `max_buffer` is 4096, see defect 8) and 640 maximum-size slots so that exactly 100 bits stay free.
8. **Bulk fixtures** use a documented LCG generator (`slots_gen`) so `full650`, `over650` and `near_full` stay small JSON files (23 to 35 kB). `build.normalise(spec)["slots"]` gives the explicit slots.
9. **`bad_*` / `oob` / `desync_length` / `truncated` fixtures** are W1 with exactly one defect each; the hash and L are recomputed so the defect is the only reason for the refusal.
10. **`hdr_firefight`**: the chdr block has no field for the firefight difficulty, so the chdr campaign fields stay zero; `hdr_campaign` fills the chdr campaign fields.
11. The bit writer's method is `getbytes` (not `to_bytes`) because `tests/py39_lint.py` flags every `.to_bytes(n)` call without a byte order.

## 6. Spec defects, ambiguities and findings (section numbers)

1. **C.4 `hdr_long_text`: the SHA-1 is not reproducible from the text.** "both author names 16 chars with no NUL; title and description 128 units with no NUL" does not say which characters. Found by search: **both names `ABCDEFGHIJKLMNOP`, title `T` x 128, description `D` x 128** give `34925a92...f343` (header end 4951, end 8666, L 1084 also match). The other four rows follow from the text alone.
2. **C.1 / 3.2: "name bytes `41 00`" means n = 2** (the letter and its NUL): that is why W1's header ends at 1255 and not 1239 (3.2's formula with n = 1). Not an error, but easy to misread; `hdr_min_text` is the n = 1 case.
3. **2.8, 2.11: the value of fileLength in a `_cmp` file is `U`** (decision 4). A reader's consistency check "fileLength equals the real length" (3.2) must not warn on `cmp`, `fsm` and `trailer` fixtures: the field counts through `_eof` of whatever is stored (`_fsm` and a trailer are outside it, 2.9 / 2.1).
4. **2.8: `_cmp` wrapper version/flags are unspecified** (decision 2). 2.9: "fixed fields of 0x1C4 bytes" does not say whether the 12-byte header is inside (decision 5).
5. **2.12 / 2.7: class `zero` (stored length `00 00 00 00`): the hash input is unspecified** (L = 0 or 0x7000 in the digest?). No fixture was built for it; `length_capacity` covers class `capacity`, which is well defined.
6. **3.10 rule 3, (b) "refers to a present label entry" and (c) `folder < quota_count`** are `I`; in W1-like fixtures the wrong GUID hypothesis (guid=True on a v31 file) is rejected by (c) in the full walk and by the length test (rule 2) when (c) is off. Every `design.must_reject` was verified both ways, so no fixture depends on (b) or (c) alone for a *designed* rejection.
7. **3.10 rule 1 vs DEC-3.10: what "every hypothesis" means for `OutOfBoundsPositionError`.** Rule 1 says the error is raised "if every hypothesis is rejected for that reason at the same slot", DEC-3.10 applies the selection to one GUID value at a time. A wrong GUID reading shifts the walk by 128 bits and can never fail at the same slot index. In `oob` all hypotheses of the version-implied GUID value fail at slot 5 (`expect.error = OutOfBoundsPositionError`); the other GUID value fails elsewhere (`oob_all_hypotheses_same_slot: false` in the walker result). A literal "every" would turn this fixture into `DesyncError`. G3 should implement the per-GUID-group reading (it is the only one under which `OutOfBoundsPositionError` can ever be raised for a version-31 file).
8. **3.6 vs 3.4: capacity is practically unreachable with RVT's 4096-byte label buffer.** With dataLength <= 4096, the longest header, 256 labels, 256 quota rows and 651 slots of 235 bits the stream is at most 200,570 bits (87.4 % of the 229,376-bit capacity, 28,806 bits free; U-20 builds this file to prove it). 3.6's remark that capacity "can only be exceeded by an unusually large label table" is true only for a buffer above 4096 bytes, which the 13-bit field allows (up to 8191). `near_full` therefore has an 8006-byte buffer; if the library caps dataLength at 4096 it would refuse this fixture and `E_CAPACITY` could never trigger from a legal file.
9. **9.3 U-09 wording "range = 2^20 x 0.000520833"**: bounds are float32, so the exact JS threshold is not representable as a difference of two stored bounds. The fixture uses min 2.870152638934087e-05 and max 546.1333618164062, whose double difference is the threshold minus 1.1e-13 (hence `ceil` = 20, `trunc9999` = 21). The second fixture `axis_threshold_f32` uses the float32-step threshold of G-AX-6.
10. **5.1 / 3.8: the raw `extra` of a type-19 slot under `plain8`** (stored value or index?) is not stated; the builder uses the stored bits (index + 1).
11. **3.3 / 3.4: no fixture for `quota_count > 256` or `label_count > 256`** (both are errors in the spec but not in the G2 list); the 9-bit fields can encode up to 511, the builder accepts such values, they are simply not catalogued. No fixture has a non-zero tail or non-zero pad bits either (the soft checks of 3.10 rule 4 are not exercised by any listed fixture).
12. The `G-ID` rows (4.10) name objects from `Addon/objects.py`; the builder deliberately does not read that table, so those rows are transcribed data (`ids` in `codec_vectors.json`), only the folder/item split (id >> 8, id & 0x1F) is computed. The `G-REAL` row is transcribed too; this gate never opens a real file.
13. No contradiction was found in the numbers: every printed value of SPEC 4.1 to 4.10 and Appendix C, including the claims about all three axis variants at k = 15..22, was reproduced.
