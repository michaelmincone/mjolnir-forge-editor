## 4. Decisions taken in G3 (most reasonable choice, work continued)

* **D1. Shape = block list only** (kept from G1 D1): a non-block trailer after `_eof` never changes the shape. The real file (trailer 29,911 bytes) makes this decisive: with SPEC 2.10's literal reading
  (`other`) the only real map variant could never be modified.
* **D2. Hypothesis order**: the GUID value implied by the body version first; inside a GUID value `flag8` before `plain8`; inside a rule the axis triples in first-seen order with the `ceil` triple of the double range first.
* **D3. Selection**: the rule of DEC-3.10 is applied to the accepted hypotheses of one GUID value at a time (the version-implied value first; the other value only when the first has none, with `W_GUID_VERSION_MISMATCH`).
  `OutOfBoundsPositionError` is raised when **every hypothesis of the version-implied GUID value** is rejected for `in_bounds == 0` at the same slot (G2's defect 7: the literal "every hypothesis" can never fire for a v31 file).
  Several accepted with identical decodes (same slots, quota rows, end, GUID bits) -> the first in preference order, `type19_status = undetermined` when both rules are among them; different decodes -> `AmbiguousLayoutError`
  (candidates: hypothesis, end bit, first differing slot). `ReadOptions.hypothesis_filter` ({type19, axis_bits, guid}) restricts the set.
* **D4. Rejection reasons** (`HypothesisReport.reason`): `oob parent folder label upface overrun length quota_count labels`. A check runs when its field is read, so the reported reason of a rejected hypothesis can differ from the builder's
  (the slot is the same in all 90 rejected rows of the 40 positive fixtures; the reason differs in 16, where this reader flags `folder` and the builder `oob` or `parent` later in the same slot). Rejection by one of the two unsourced checks
  (`folder` below the quota count; label entry present) is flagged `unsourced`, and `unsourced_only` when the walk is accepted with those two checks off.
* **D5. Lenient**: `ReadOptions(strict=False)` retries a strict `DesyncError` with the two unsourced checks off; the model is marked `lenient` and warns `W_LENIENT_PARSE`. `verify_mvar --lenient` prints that walk and still exits 1.
* **D6. Diagnostics**: `walk.diagnose` is a walk that does not stop at the first violation (it keeps reading with the same widths, like the JS prototype) and lists them; `verify_mvar` prints it for every rejected hypothesis, so a failing real file shows where each
  hypothesis desynchronises. It is never used to build a model.
* **D7. Raw ranges**: header, fixed body, label table, GUID block, every slot and the **tail** (end of the quota table to the capacity, pad bits included) are kept as `BitString`s and re-emitted; the tail is shifted with the quota table and may lose only zero bits at the capacity.
* **D8. Read-time warning codes** that SPEC 7.3 does not list (all severity `warning`): `W_FILE_LENGTH_MISMATCH` (header fileLength against the length through `_eof`, so `_cmp`, `_fsm` and trailer files do not warn), `W_MAP_ID_MISMATCH` (body copy), `W_CHDR_MISMATCH`, `W_CHDR_MISSING`,
  `W_MAP_UNKNOWN`, `W_UNKNOWN_OBJECT_IDS`, `W_TAIL_NONZERO`, `W_PAD_BITS_NONZERO`, `W_LABEL_LENGTH_MISMATCH`, `W_LABEL_TEXT_UNDECODABLE`, `W_QUOTA_MIN_ABOVE_MAX`, `W_UP_DEAD_ZONE`, `W_TEAM_ABOVE_9`, `W_LENIENT_PARSE`. A clean file has none (the real file has none).
  `W_GUID_VERSION_MISMATCH` fills its `%s` with "present" or "missing".
* **D9. ObjectRecord details**: `type_name` is `"Unknown (0x%04X)"` for an id the map's stock table lacks and `"Unknown (no type)"` when folder or item is absent (`type_id` -1, `stock` False); `other_a` of a type-19 object is `stored - 1` under `plain8` and the index or -1 under `flag8`;
  `physics` is the raw 2-bit value (2 stays 2); `parent_slot = parent_raw - 1`; `raw` / `raw_bits` are the slot's original bits; positions are cell centres (4.2). `MapInfo.labels` holds the decoded text of each entry (`''` when absent, UTF-8 with a Latin-1 fallback).
* **D10. Plain form**: the compressed label block is stored whole in `comp_hex` (4-byte uncompressed-size prefix + zlib stream); the header keeps `raw_hex` / `raw_bits` and, besides the text, `title_units` / `description_units`; an all-zero tail is not written (`tail_hex` empty, `tail_bits` gives its length); `views` is ignored. `from_plain` builds the plain block layout
  (also for a `_cmp` source) through the container's forced rebuild, so every length, `_eof` and hash is recomputed; a hand-written minimal dict gets defaults (version 31, `salted_be32` with a big-endian length, a `chdr` built from the header fields, axis bits from the bounds, `flag8`).
* **D11. `verify_mvar` extras**: `--force-selfcheck-failure NAME` (hidden, a testing hook for exit status 3), several files give the worst status, `--json` writes through `write_atomic` and refuses the repo tree. A report is built without ever raising for a bad file; a library bug while reporting becomes exit 3 with a sentence.
* **D12. Edits outside the G3 file set**: (a) the real sample folder is now a third default protected folder (`io.DEFAULT_PROTECTED`, `helpers_snapshot.PROTECTED_ROOTS`; the expected list of `test_io_policy` changed with it; the U-21 snapshot now includes the real `.mvar`);
  (b) `tests/py39_lint.py` no longer flags `MapVariant.from_bytes(data)` as `int.from_bytes` (narrow exemption by receiver name, with a lint test); (c) `tools/mutate_g3.py`, `tests/unit/helpers_g3.py` and `docs/mvar/notes/real_mvar_0aaaf8c7.md` are additions.
* **D13. The JS oracle** (U-23) loads Cobb's GPL files from their original place into a `node` `vm` context; only a small harness (written by us) lives in the test. Nothing is copied or vendored.
* **D14. Refusal tests never aim at real folders**: a target that must be refused inside a real protected folder is chosen *below an existing file* of that folder (see section 10), so even a broken policy cannot create anything there.

## 5. Spec defects, gaps and deviations found in G3 (SPEC section numbers)

1. **2.10 vs 2.1 / 7.3 / U-10 (trailer after `_eof`)**: confirms G1's S1, now with the real file as the deciding case (D1). SPEC 2.10 should drop "or carries a non-block trailer after `_eof`" from the `other` row; `docs/mvar/notes/G2.md` line 99 and `trailer.json`'s `expect.shape` ("other") should say `plain4`.
2. **3.10 rule 1 vs DEC-3.10**: "every hypothesis" must mean "every hypothesis of the version-implied GUID value" (D3; G2's defect 7).
3. **9.3 U-23**: the JS prototype cannot check quota rows: its loop tests `this.unk2B2` (the field is `unk02B2`), so it reads no quota rows. It also never reads the campaign / firefight header tails (`this.gameMode`, X23) and knows no GUID block.
   The test therefore compares header, bounds, budgets, labels and slot fields, and pins the quota typo.
4. **6.3 `choose(stream, L, version_hint)`**: the meaning of `version_hint` is unspecified. Here it is the `mvar` chunk version (informational); the body version, which orders the GUID hypothesis (3.3), is read from the stream. `L == 0` stands for the four stored zero bytes (class `zero`).
5. **3.2 "fileLength equals the real length"**: "real length" must be the length *through `_eof`*; for `cmp`, `fsm` and trailer files the stored number counts that, not the file size (G2's note 3). Implemented as `W_FILE_LENGTH_MISMATCH` (D8).
6. **3.10 rule 3 (b) and (c) (unsourced checks)**: the real file satisfies both (610 of 610 folders below `quota_count`, every label index names a present entry). That does not source them, but it shows they do not refuse a valid file.
7. **7.3 `W_GUID_VERSION_MISMATCH`**: the `%s` is unspecified; "present" / "missing" here. **7.2 `DesyncError`**: the pattern has "at slot %d, bit %d" but the best candidate can fail without a slot (length test, prefix); the sentence then reads "at bit N".
8. **3.6 / 3.11 labels**: an `ObjectRecord` carries the label *index*; the text comes from `MapInfo.labels`. The spec's phrase "label via stored offsets" is met by `LabelTable.text`.
9. **6.6 `comp_hex`** is not defined (zlib stream only, or with the size prefix); D10 chooses the whole stored block.
10. **5.3 / 5.4 / 7.5 vs the plan D10 / D10a (not a defect, a gap)**: the spec assumes a template with quota headroom; the real template has none for blocks (section 7).
11. **Still unverified after the real file** (it contains none of them): the type-19 rule (no type-19 object), the 128-bit GUID block of v32 (the file is v31), the parent-link encoding (no parent link), out-of-bounds records, `_cmp` / `_fsm` shapes, `plain_le32` with a little-endian length, the meaning of the placement bits 0x02 / 0x04 / 0x08 / 0x10 (section 7 of the real-file note) and the orientation conventions of 4.6 (the angle code is consistent: raw 8,192 = angle 0 is the most common value).
12. **9.2 / run_tests**: `tools/run_tests.py --only` takes several substrings; the mutation harness relies on it. No change needed.

### Options for the quota problem (decision for the orchestrator)

The template is a finished matchmaking variant: 42 of 82 rows are non-zero, 39 of them have `maximum == placed`, 40 rows are `(0, 0, 0)`. Any added object whose row has `maximum == placed` or `0` exceeds the maximum (SPEC 7.5 `E_QUOTA`).
(a) Keep the spec: no Block can be added to this template. (b) Add an explicit, opt-in, loudly flagged *unverified* option in G5 that raises `maximum` of an affected row to the new `placed` (never lowers a value, never touches `minimum`); nothing known says whether MCC or the Xbox honours the file's
`maximum` or re-derives it from the scenario (SPEC 10.2). (c) Use another template (none exists on this machine). Rows with real headroom today: 4 Rocket Launcher (+1), 6 Sniper Rifle (+1), 7 Spartan Laser (+1). My recommendation: (b), default off, with the warning text "quota maximum raised: unverified".
For the cached type / placement byte of a new Block: the real file has no Block to copy from, but it confirms that Structure and Scenery objects have cached type 0 (the `assumed_zero_groups` rule of 7.4) and that structure objects use placement 0xCC (phased) or 0x0C.
