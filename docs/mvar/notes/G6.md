## 4. Defects found by running the real thing (all fixed in the glue)

1. **Float32 noise wrote every axis-aligned rotation one angle cell low.** `rotation_euler.z = -pi/2` is stored as the float32 `-1.5707963705`, so the forward vector is `(1, -4.4e-8, 0)`, a yaw of `-4.4e-8` rad; the angle quantiser FLOORS
   (SPEC 4.4/4.7), and every quarter turn is a cell edge (4096 cells per 90 degrees), so the block got raw angle 8191 instead of 8192 and golden E2 failed (the spec's "`rotation_euler.z = -pi/2` gives raw 8192" is only true in float64).
   `mjolnir.snap_axis` sets direction components below 1e-6 to zero and renormalises (`pose_from_matrix` for forward and up; 1e-6 rad is 380 times smaller than a cell and 50 times smaller than the change tolerance). Tests: b18 (E2 with and without library), b23.
2. **Blender 5.2.1 bug (probed): assigning a bytes value to an ID property key that already holds bytes stores an EMPTY value** (`scene['k'] = a; scene['k'] = b` gives `b''`; a fresh key or a key deleted first works).
   `state.set_from_load` now deletes both keys before assigning, so a leftover template can never swallow the next file (it could only happen after a hand-deleted `mjolnir` key, but a silent empty template would pass `E_TEMPLATE_CORRUPT` only by luck).
   Unit test `test_a_template_key_that_already_exists_is_deleted_before_it_is_assigned`; b16 tampers with the template by deleting the key first for the same reason.
3. **A slot that failed to import and holds a non-stock object bypassed the stock rule** (polish item 8): the library keeps a slot it was told was not imported exactly as it is, with no stock check (`W_SLOT_NOT_IMPORTED`). The importer now records `failed_nonstock` (`{slot: type name}` from `rec.stock`);
   the exporter refuses it with the new glue code `E_FAILED_SLOT_NOT_STOCK` (same rule as an imported unrecognised object, DEC-7.4) and, with "Keep objects this tool does not recognise", keeps it with `W_FAILED_SLOT_KEPT`. The scene panel says so. The library's own `W_SLOT_NOT_IMPORTED` warning and `NOT IMPORTED slot N` diff line were already in the report (b05, b16 assert both); the Info line now ends " N not imported earlier, left unchanged."

**Decision for item 5** (which numbering preserves the most `.blend` files): the shipped add-on is `Blender (Download a Release, Not Me!)/forge.py` (releases 0.9.9.0 to 0.9.9.2, updated 2026-06); its first item is `1X`, so a scene saved by it stores 1X=0 ... 330X=4.
`Addon/mjolnir.py` at HEAD (2024, no `1X`) stores 33X=0 ... 330X=3. The maintainer's own commit `4eddf40` (2024-06-22, "Added 330x cosmic scale, 1x scale") already shifted the numbers by one for forge.py, so files saved by releases before 0.9.9.0 that
stored an explicit convention read one item up in forge.py too; nothing can repair that. Most users never change the convention (the property is then not stored and reads the default). forge.py's numbering is the newest, the shipped one, and what the working tree already had by position;
it is now pinned. Side effect, intended by SPEC 8.7 #3: a scene that never stored the property now reads `47X` instead of forge.py's (buggy) `default=2` = `71X`.

## 7. Decisions (most reasonable choice made, work continued)

1. **Stub tests keep their stub `run`; the real catalogue is `run_real`** in the same file (same B-id, same topic, fixtures of the independent builder and the real file, expectations from the independent decode). `REAL_ONLY` files (b15, b16, b18, b20, b03r) are not part of a stub run (a stub cannot do them);
   under `--provider real` b03 is replaced by b03r (`REAL_VARIANT`). A stub test with no real variant would SKIP and fail the gate; there is none.
2. **`E_FAILED_SLOT_NOT_STOCK` refuses by default** (not just a warning): the owner's rule is "stock objects only, refuse with a clear error otherwise"; a slot that did not import is exactly where that rule used to have a hole. The way out is the existing checkbox.
3. **b16 asserts the library's own wording** for each code. Some codes can only be reached by a script (the Add menu offers no weapons and no entry beyond the quota count), so those cases build the object with `mjolnir.create_forge_object` (what Convert / an older `.blend` makes).
4. **The real library is never copied**: b17 copies the stand-in even under `--real-library`; `--real-library` only links it. The `.blend` files saved by the tests link it by relative path and are written to the private temp folder.
5. **b20 builds and installs its own package** in a scratch profile whatever way the suite was started (it needs `/usr/bin/python3` 3.9 for `build_package.py`; without it the test SKIPs).
6. **`tools/run_blender_tests.sh` default stays the stub provider** (G4's contract); `--provider all` is the one-command full run.

## 8. Spec defects and gaps found (section numbers)

1. **4.7 / 9.4 B-18 / Appendix C.3 E2**: "`rotation_euler.z = -pi/2` yields raw 8192" holds only in float64; Blender stores float32 and the flooring quantiser puts the noisy yaw one cell low (section 4 item 1). The glue now snaps; the spec should say so.
2. **8.3**: a top-level bytes ID property survives save + open (probed in the spec) but not an in-place re-assignment in 5.2.1 (section 4 item 2).
3. **9.4 B-16**: `no free slot` is unreachable through the operator (the limit is 650, a file has 651 slots, so `E_TOO_MANY` always comes first; b16 asserts that `E_NO_FREE_SLOT` is absent from the 651 case); `label out of range` is reachable only when the stored label list and the file disagree
   (the label enum offers present entries only; b16 forces it by editing the stored list); `unknown cached type` and `folder beyond the quota count` need objects the Add menu does not offer.
4. **8.6 / G5 defect 12**: the per-map filter needs the folder of a name (and the quota count) and the frozen api has neither; solved with the non-frozen `provider.object_folder` (section 6).
5. **7.3 / the `E_QUOTA` text**: `Palette entry 66 (Antenna, Small) would have 8 placed` names the FIRST item of the folder, not the object the user duplicated (`Cover, Large`, item 7 of the same folder). The quota row is per folder, so the number is right and the name is arbitrary. Cosmetic; a folder-level wording would be clearer.
6. **5.6 / DEC-5.6 gate**: even a plain duplicate (same orientation as its source) needs "Allow unverified rotation export" and says "has a new or changed rotation". The reason (every new object writes an orientation) is not in the text.
7. **4.9 on the real file**: a move below the position tolerance `max(1e-3, cell/2, 2 ulp) = 0.0039` is not written at all (a 0.002 nudge leaves the file byte-identical, b23 real); correct by the spec, surprising in use.
8. **9.4 B-07 "Sprint resolves per map"** is really "one id, two internal names": 0x1E00 on all 20 maps, `sprint_spartan` on 13, `arm_sprint` on 7 (already D8-4 of G0); b07 shows it on Forge World and Breakneck.
9. **9.4 B-03 / B-20** name `--provider real` variants as separate files (`b03r`); the catalogue says nothing about what a stub run does with real-only files (here: not part of it).
10. **8.4 step 8 / 10**: no bound on console output was specified for a mass failure of the importer (610 tracebacks); now bounded (item 4 of the polish list).
