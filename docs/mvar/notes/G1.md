## 2. API cheat sheet for G3 and G5

```python
from mvarlib import blf, hashing, bitio, ugc_header          # (tests: sys.path.insert(0, <repo>/Addon))

f = blf.parse(data)                      # BlfFile; raises BlfFormatError / UnsupportedVariantError (SPEC 7.2 sentences)
f.shape        # 'plain4' | 'plain4+fsm' | 'cmp4' | 'cmp4+fsm' | 'other'   (block list only, see D1)
f.chunks       # logical Chunk list in file order (a _cmp-wrapped payload appears as the inflated block); f.trailer = opaque bytes after the last block
f.find('mvar') # Chunk or None;  f.payload = first registered payload chunk;  f.blocks() / f.layout_text() for reports
f.warnings     # parse-time Issues (W_CHUNK_VERSION_UNEXPECTED)
f.eof_endian, f.eof_value_ok             # '>' | '<' ; False = the _eof value matched neither order (forced rebuild writes '>' )
f.flavour      # HashFlavour of the first payload block, or None (unknown)

c = f.find('mvar')
c.sig c.version c.flags c.offset c.size c.raw c.cmp    # raw = exact block bytes (inflated for _cmp); offset/size = position in the ORIGINAL file
c.stream                                  # the full bit stream, stream_capacity (0x7000) bytes;  c.pad = the 4 bytes after it
c.stored_length c.length_endian c.length_raw c.zero_length c.hash_stored
c.flavour                                 # HashFlavour (== ('>', 'salted_be32') too) or None
c.analysis                                # hashing.HashAnalysis: readings, every candidate, hash_length (the L that entered the matching digest)
c.set_stream(stream_bytes, length=None)   # patched mode: new stream (zero padded to 0x7000), new stored L; marks the chunk dirty. CapacityError if too long
f.drop_fsm()                              # fsm_policy = DROP; counts as a modification

f.to_bytes()                              # clean -> the ORIGINAL bytes (same object); dirty -> patched output
f.to_bytes(force=True, stream_length={'mvar': L}, flavour=HashFlavour(...))
r = f.render(force=..., stream_length=..., flavour=...)   # r.data (bytes) + r.issues (W_CMP_EXPANDED, W_FSM_STALE, W_TRAILER_KEPT, W_HASH_UNKNOWN, I_HASH_ZERO)
```

How to use it from the model (what G3 / G5 must pass):

* **L (`stream_length`)**: class `ceil_end` -> `ceil(end / 8)`; class `capacity` -> `0x7000`; class `zero` -> `0` (writes `00 00 00 00` and hashes the whole capacity, or whatever length the template's own hash covered). Omitted -> the stored L is kept (right for opaque payloads such as `mpvr`). It is ignored when the file is clean and `force` is false.
* **Embedded file length**: never patch it yourself. A forced rebuild, and any rebuild whose total file length changed (a `_cmp` expansion), re-stamps it (bit 4 of an `mvar` stream, bit 72 of an `mpvr` stream) with a masked write, then hashes. A patched save of a plain shape leaves it as given in the stream you passed (SPEC 5.4 step 7).
* **`hash_policy`** (`ExportOptions`): build the flavour from the template, e.g. `HashFlavour(c.length_endian, 'plain_le32')`; `flavour=` only chooses the recipe/byte order when a hash is written (forced or dirty). It never turns a clean unforced save into a rewrite (so "nothing changed -> template bytes" of 5.10 step 10 holds).
* **Warnings of the writer** (`W_HASH_UNKNOWN`, `I_HASH_ZERO`, `W_CMP_EXPANDED`, `W_FSM_STALE`, `W_TRAILER_KEPT`) come back in `render().issues` with the exact 7.3 texts; `W_CHUNK_VERSION_UNEXPECTED` is in `f.warnings`. `W_FSM_STALE` / `W_TRAILER_KEPT` are reported only for a real modification (dirty, or a `_cmp` expansion), not for a forced rebuild that reproduces the input.
* **Refusals the container already raises**: not `_blf` first, tiling errors, no `_eof`, > 256 blocks, bad `_cmp`, stored length invalid in both orders (all `BlfFormatError`, SPEC 7.2 wording); `mvar` size != 0x7028 and chunk versions 12/13/14/50/51 (`UnsupportedVariantError`; any other chunk version outside {31, 32} only warns). Not raised here (G3 does it): "game variant, not a map variant" (`find('mpvr')` is set), "no mvar block" (`f.layout_text()` lists the blocks), body version, content type.
* `to_bytes(force)` / `render` on shape `other` raise `BlfFormatError("This file's block layout (...) cannot be modified safely.")` (the E_CONTAINER_SHAPE text); passthrough of `other` works.
* Bit I/O: `BitReader.read(n)` / `read_signed` / `read_bytes` / `read_cstring(max)` / `read_u16string(max)` / `read_bitstring(n)` / `slice(a, b)`; overrun raises `BitOverrun` (a `DecodeError`, so an `MvarError`) and leaves `pos` unchanged for **every** reader method, the string readers included (D15). `BitString` can be copied, deep-copied and pickled (D14). `BitWriter.write(v, n)` is strict (`EncodeError` unless `0 <= v < 2**n`), `write_signed`, `write_masked`, `write_bytes`, `write_bitstring`, `write_to_bitpos(pos, n, v)` (masked, cursor not moved), `write_cstring` / `write_u16string` (strict: must read back as themselves; all-or-nothing: a refused string writes nothing, D12), `getvalue(total_bytes)` (zero padded, `CapacityError` if longer), `getbits()`.
* Header: `read_header(r)` leaves `r` just after the header and returns a `UgcHeader` with `raw` (BitString), `start_bit`, `end_bit`, `bit_length()`; at bit 0 for an `mvar`, after the 68-bit prefix for an `mpvr`. Content type is *not* checked (G3 raises `UnsupportedVariantError`); `header.content_type` is the decoded value (stored - 1).

## 3. Decisions taken in G1 (most reasonable choice, work continued)

* **D1. Shape id = block list only.** `plain4` etc. describe `_blf, chdr, <registered payload>, _eof [, _fsm]` for any registered payload (so the real `mpvr` game variants are `plain4`). A non-block remainder after `_eof` is `BlfFile.trailer` and does not change the shape; see defect S1.
* **D2. `BitOverrun`** is defined in `bitio.py` as a subclass of `DecodeError` (SPEC 6.3 names it but `errors.py` is frozen). Calls with a bad argument (negative or non-int width, non-bytes data) raise `InternalError` (a library bug, SPEC 6.2); a value that does not fit raises `EncodeError`.
* **D3. `HashFlavour`** is the frozen dataclass of 6.3 and additionally compares equal to, hashes like, unpacks as and indexes like the pair `('<', 'salted_be32')`, because SPEC 9.1 / 9.3 write the detection result as a pair.
* **D4. All-zero stored length.** Four zero bytes are tried as the lengths `0` and `0x7000` (SPEC 2.7). The byte order cannot be detected then; it is reported as the layout default (`>` for `mvar`, `<` for `mpvr`) and kept. The zero class is written back as `00 00 00 00`; if a caller asks for it (`stream_length=0`) on a template that was not in that class, the hash covers the whole capacity.
* **D5. Candidate order.** Recipes are tried in the table order of 2.7 (`plain_le32, salted_be32, salted_le32, plain_be32, data_only`, then `zero`); only `L == 0` makes two recipes identical (LE32 = BE32 = 4 zero bytes), then the first in that order is reported. `zero` (stored hash all zero) is classed before any digest; it is also the last row of `candidates()`.
* **D6. Unknown hash.** A stored hash that matches nothing is rewritten as `salted_be32` with the template's valid length byte order (DEC-2.3 case 3) and reported as `W_HASH_UNKNOWN` for every payload spec; `PayloadSpec.default_recipe` is the recipe used for this (it is `salted_be32` for `mpvr`, `None` = `salted_be32` for `mvar`).
* **D7. Render modes.** Passthrough = the original bytes object. Patched = a payload chunk got `set_stream`: only that block changes (stream, stored L, hash; the 4 pad bytes and the block header are copied from the template); the three file-length stamps are re-written only when the total file length changed. Forced = SPEC 2.11 steps 1 to 8 in order. A clean `_cmp` chunk keeps its wrapper bytes in every mode except forced; a forced or dirty one is written expanded (`W_CMP_EXPANDED`).
* **D8. `_cmp` inflate** is capped at the declared size (maximum 16 MiB declared), requires the end of the zlib stream, the exact declared size and an inner block whose own size field equals its length; bytes after the zlib stream inside the wrapper are not an error. A `_cmp` that wraps anything but `mvar`/`mpvr` stays an opaque `_cmp` chunk (shape `other`).
* **D9. After `_eof`** a following run of bytes counts as further blocks only while each looks like a block (a signature of four ASCII letters, digits or underscores, size >= 12, fits in the file); the first one that does not starts the trailer (zero padding, text, truncated blocks). Since section 8 the signature test is ASCII only: `str.isalnum` also passed Latin-1 letters such as `0xE9`, so random trailer bytes could be mistaken for a block and turn a modifiable `plain4` into shape `other`.
* **D10. `chdr` parse/build keeps every byte** (pads at 0x11, 0x3B, 0x44 and in both author records, the unknown regions at 0x294 and 0x2B8, block version/flags), so `build_chdr(parse_chdr(b)) == b` for *any* 0x2C0-byte `chdr` block, not only the real ones (the reference `build_chdr` assumed zero pads). A field of the wrong length raises `EncodeError` instead of resizing the block.
* **D11. `compare_chdr_header(chdr, header, extended=False)`** returns the list of disagreements (content type, file length, map id, title, description; `extended=True` adds ids, activity, game mode, engine, category, both authors, engine icon). It is advisory and raises nothing (SPEC 3.2 "consistency checks" are warnings).
* **D12. Strict string writers.** `write_u16string` / `write_cstring` raise `EncodeError` for a string that the reader could not read back (empty, NUL before the last unit, shorter than the maximum without a closing NUL, longer than the maximum). A string of exactly the maximum length without a NUL is legal (`hdr_long_text`). Both writers check every unit (an integer of the unit's width) and the whole string before the first bit is written, so a refused string leaves the writer untouched (section 8, defect 2).
* **D13. Test structure.** T1 tests need the 8 real files: without `--samples` they SKIP with a notice (listed by the driver), with `--samples` a missing or incomplete set (fewer than 8 paths / 5 distinct contents) FAILS. `PASS` lines are printed when the class finishes so they are not glued to unittest's dots. Synthetic header tests use the spec's reference W1 builder (`docs/mvar/reference/w1_build.py`, loaded with `importlib`, no side effects) as an outside source of bytes; container tests use `helpers_container.py`.
* **D14. `BitString` copy and pickle.** `BitString` forbids attribute assignment, which broke `copy.copy`, `copy.deepcopy` and `pickle` (they restore the slots by assignment) and with them `copy.deepcopy(UgcHeader)`. It now defines `__copy__` and `__deepcopy__` (an immutable value is its own copy) and `__reduce__` (rebuild through the validating constructor, all pickle protocols 0 to 5). SPEC 6.3 `MapVariant.copy()` may therefore be a plain `copy.deepcopy` of the model; the container objects (`BlfFile`, `Chunk`, `HashFlavour`, `HashAnalysis`) and `UgcHeader` were checked too and have tests.
* **D15. Atomic string readers.** `read_cstring` and `read_u16string` restore `pos` to where the string started when a unit does not fit, so the documented "a failed read leaves `pos` unchanged" holds for every `BitReader` method. The exception's own `pos`/`requested` still describe the unit that did not fit.

## 4. Spec defects, gaps and deviations found in G1 (SPEC section numbers)

* **S1. 2.10 vs 2.1 / 7.3 / U-10 (trailer after `_eof`).** 2.10 puts "a non-block trailer after `_eof`" in shape `other` (modified save refused), but 2.1 ("a modified save keeps it verbatim and warns `W_TRAILER_KEPT`"), 7.3 (`W_TRAILER_KEPT`) and U-10 ("trailer after `_eof` kept") need it to be modifiable; the warning would be unreachable otherwise. G1 keeps the shape as the block list (`plain4`) and the trailer in `BlfFile.trailer`: a modified save keeps it and reports `W_TRAILER_KEPT`. G2's fixture `trailer` (512 bytes) round-trips through passthrough and forced rebuild. **Resolved reading for `NOTES.md`** (an independent verifier confirmed it): a non-block trailer after `_eof` does not change the shape (`plain4` stays modifiable, `W_TRAILER_KEPT` on a modified save); only a *block* after `_eof` other than `_fsm` makes it `other`. G2's own `tests/golden/fixture_specs/trailer.json` says `container.shape = "plain4"`; only the table row of `docs/mvar/notes/G2.md` (line 99, "`trailer` | other, 29,993 ... (shape `other`)") still says `other` and should read "`plain4`, 29,993 ... (shape `plain4`, `W_TRAILER_KEPT` on a modified save)". The orchestrator should also change SPEC 2.10 (the `other` row: "or carries a non-block trailer after `_eof` (2.1)" should go) so it agrees with 2.1, 7.3 and U-10; G1 may not edit the spec or G2's notes.
* **S2. 9.3 U-04 / 3.4 (zlib streams in the real files).** "`test_user_funcs_and_recursion.bin` has none, so 4 of the 5 distinct contents" is not what a scan finds: each of the 5 distinct contents holds the same 535-byte compressed table (inflated 535, compressed 422 bytes) and 4 of them hold a second, larger one (inflated 4784 / 502 / 1492 / 380), 9 streams in all (pinned in the test by bit position, compressed and inflated length). The "at least 4 streams" assertion holds. In these tables the size field in front of the `u32` uncompressed size is **12 bits** wide and holds compressed length + 4 (the Forge label table of 3.4 uses 13); the scan accepts 11 to 13 bits. Levels 7, 8 and 9 reproduce all 9 streams on zlib 1.2.12 and 1.3.1; level 6 does not. **Resolved reading for `NOTES.md`** (the verifier's own bit-shifted scan found the same 9 streams): all 5 distinct contents carry the 535-byte table, including `test_user_funcs_and_recursion.bin`, so SPEC 9.3 U-04's "has none, so 4 of the 5 distinct contents" should be corrected to "every one of the 5 distinct contents has at least one stream, 9 streams in all" (the assertion "at least 4 streams" stays true).
* **S3. Appendix C.4 `hdr_long_text`.** The text gives lengths only, but the stored SHA-1 depends on the characters. Both author names `ABCDEFGHIJKLMNOP`, title 128 x `T`, description 128 x `D` reproduce `34925a92...f343` (found by search; G2 found the same independently). Pinned in `test_header_real.py`. All five C.4 rows (header ends 1271 / 1307 / 1289 / 4951 / 647, end bits, L, stored SHA-1) are reproduced by the header codec.
* **S4. 6.3 `BitOverrun`** is used by the contract but is not in the 6.2 hierarchy (and `errors.py` is frozen): defined in `bitio.py` (D2). **6.3 `candidates(chunk, spec: PayloadSpec)`**: `PayloadSpec` lives in `blf.py`, which imports `hashing.py`; the hashing functions therefore accept any object with the `PayloadSpec` attributes (duck typing, no import cycle).
* **S5. 6.3 `BlfFile.to_bytes(force, stream_length)` has no way to pass a hash flavour**, but `MapVariant.to_bytes(force, flavour)` and `ExportOptions.hash_policy` need one: added the optional keyword `flavour` (and `render()`, which also returns the writer's issues). 2.11 step 4 is realised by `stream_length`.
* **S6. 2.7 / 7.2 wording "stored length invalid in both byte orders".** "Invalid" is about the four bytes, not about one value: the bytes `00 01 00 00` are an invalid big-endian value (65536) but a valid little-endian 256, and are read as 256. The claim "both readings are valid only for four zero bytes" holds (checked for every length 1 to 0x7000). Tested.
* **S7. 2.11 step 3 / 3.2 header formula.** The E_h formula of 3.2 omits the 8-bit engine icon that a *game* variant stores; `UgcHeader.bit_length()` includes it, so it equals the consumed width for both kinds (1535 / 1183 / 2287 / 2271 / 2575 bits on the real files).
* **S8. NOTES.md D8-11 (G0) confirmed.** The reference `blf_container.py` defaults to the `mpvr` layout with a little-endian length (wrong for `mvar`), hard-codes sample paths and its `--selftest` writes a transient `.mvar`. None of that was carried into `Addon/` or `tests/`; the `PayloadSpec` registry replaces it. The reference `build_chdr` also assumed zero pad bytes (D10).
* No change to a frozen file was needed.

## 5. Mutation check (the tests bite)

`tools/mutate_g1.py` applies one source mutation at a time to a copy in a fresh temp directory (never inside the repo) and runs the G1 tests against it with `run_tests.py --samples --only ...`. **112 mutants: 106 killed, 6 documented equivalent (0 other survivors), identical on Python 3.9.6 and 3.13.13.** (The first 71 are the original set; the 41 added in the fix round of section 8 cover the gaps an independent verifier found with its own 101 mutants.)
Families: the masked write (no clearing of the target bits; the RVT clobber hazard for byte-aligned starts in general and for n < 8; `patch_bits` wiping the neighbours; the `write_to_bitpos` cursor; the clobber applied after the embedded file length, which only the random-stream tests see because the W1 neighbour nibble is zero), reader and writer semantics (LSB-first reading, `read_signed`, oversize values accepted, NUL kept, overrun off by one, `bit_length` ignored, zero-width read consuming a bit, `u16` unit width, padding of `BitString`, `getvalue` flooring), hashing (a salt byte, LE/BE swapped in `salted_be32` and `plain_le32`, zero length not also tried as the capacity, hashed region one byte long, candidate order, `compute` accepting short data, valid-length range, matched length), container (embedded length not re-stamped / at bit 5 / clobbering, chdr length not re-stamped / big-endian, `_eof` value not re-stamped / off by one / byte order detection swapped, hash over the stale stream, `stream_length` ignored, stored length in the wrong byte order, unknown-hash fallback recipe and byte order, warning not reported, trailer dropped, `_cmp` always expanded / inner size unchecked / compression type unchecked, `mvar` stream at +40, length at +36, `mpvr` embedded bit 71 and the `mvar` layout given to `mpvr`, version/flags taken from the wrapper, chunk version 51 not refused, unexpected version not warned, `drop_fsm` not dirty, shape without `_fsm`, block size < 12 accepted, trailing blocks all treated as trailer, zero class handling) and header (hopper tested on the stored activity, campaign/firefight widths, author name limit 15, title limit 127, engine icon condition inverted, `chdr` map id offset, `chdr` build without pads, undecoded content type, 63-bit xuid, raw range one bit short).
The six equivalent mutants cannot change any observable result; each reason is next to it in `EQUIVALENT` in `tools/mutate_g1.py`: (1) "stored zero hash is not classed zero first": the `zero` row of the candidate list matches a stored all-zero hash anyway; (2) the `BitWriter` high-water update guarded by `pos == end`: `_put` sets `pos = end` on the line before, so the guard is always true; (3) the `_cmp` inflater without the output cap: the cap only bounds memory, the size check after it raises the same error; (4) the shape gate without `eof_index != 3`: `sigs[3] == '_eof'` is checked next and blocks 0 to 2 are `_blf`, `chdr` and a payload, so the first `_eof` is block 3; (5) the unknown-hash fallback flavour with a fixed length byte order: the recipe fixes the byte order inside the digest and the stored length is written with the separate `endian` variable; (6) trying the other stored-length byte order first: four bytes valid in both orders exist only when all four are zero, which has its own row.
Besides that, the tests apply real data mutations themselves: 1-bit flips in the stream of each real file (inside the hashed region: every candidate breaks and restoring matches again; after `L`: the hash stays valid), corrupted `chdr` length / `_eof` value / embedded length / stored hash (forced rebuild restores the original, passthrough does not repair), a big-endian stored length (detected as `('>', 'salted_be32')`), tampered `_cmp` streams, and wrong chunk versions.

An extra one-off integration check (not committed, it depends on G2's builder): the 49 fixtures of `tests/fixturebuilder/build.py --out <scratch>` all parse (the 5 negative ones raise the expected container-level errors), passthrough is the identity, forced rebuild is the identity for every plain shape and for `trailer`, `eof_le`, `le_length`, `zero_hash`, `plain_le32`, `length_capacity`, and equals the independent golden `cmp_expanded` / `cmp_fsm_expanded` files for the `_cmp` shapes (DEC-2.6); dropping `_fsm` from `fsm` yields `w1_minimal`.

## 7. Things G3 / G5 / G7 should know

* The hash covers `stream[0:L]` *including* the embedded file length, so any code that changes the stream must go through `set_stream` (or a forced rebuild); never hash by hand.
* For a `_cmp` file the value of the embedded file length is `U` (SPEC 2.8): a forced or patched rebuild always writes the **expanded** total, G2's goldens `cmp_expanded` / `cmp_fsm_expanded` agree.
* `Chunk.raw` of a `_cmp` payload is the inflated block; `Chunk.size` / `offset` are the wrapper's. `f.original` is the input `bytes` (the same object when `bytes` were passed; a copy for a `bytearray` or `memoryview`).
* `BlfFile` objects are mutable only through `Chunk.set_stream` and `drop_fsm`; `render` / `to_bytes` are pure and can be called repeatedly (a model that "plans" can call it on a fresh `parse(template)` for each plan).
* Time: parsing a 29 KB map variant (about 11 SHA-1 candidates) takes about 0.1 ms, a forced rebuild about 0.03 ms (Python 3.9, Apple silicon).

## 8. Fix round after the independent verification

An independent verifier re-ran G1 and reported four findings; none broke a G1 acceptance clause. Only G1's own files changed (`bitio.py`, `blf.py`, the three test files, `tools/mutate_g1.py`, this note). `api.py` and `errors.py` are untouched.

1. **Major: `BitString` could not be copied or pickled.** `__slots__` plus a `__setattr__` that always raises made `copy.copy`, `copy.deepcopy` and `pickle` fail with `AttributeError('BitString is immutable')`, and with them `copy.deepcopy(UgcHeader)` (its `raw` is a `BitString`). SPEC 5.1 keeps `BitString` ranges in `UgcHeader`, `LabelTable`, `Slot`, guid and tail, and SPEC 6.3 defines `MapVariant.copy()` as a deep copy, so the first obvious implementation in G3/G5 would have failed.
