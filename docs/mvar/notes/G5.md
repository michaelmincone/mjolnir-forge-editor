## 3. Behaviour of `export_map_variant`, for G6 and G7

* **Order** (5.10): parse (`E_TEMPLATE_UNREADABLE`), options (`E_OPTION_INVALID`), stock map (`E_MAP_UNKNOWN`; all type checks are then skipped, so the refusal is that one error), field validation of every object,
  identity (5.5), per-slot plan, new objects, quota, container shape, object limit, capacity pre-check. Everything found is returned (`errors` is the whole list: global, per object, quota, capacity, in that order);
  `ok = False` implies `data is None`. Then apply to a deep copy, serialise (`MapVariant.render`), **re-parse the output and compare it with the plan** (an `InternalError`, never a user error, on a violation), report.
* **Passthrough**: nothing dirty, no `force_reencode`, no `fsm_policy = DROP` on a template that has `_fsm`, no `hash_policy` recipe different from the template's -> `data` is the template (`stats['mode'] == 'passthrough'`).
* **Result details**: `diff` order = claimed slots by slot (`kept` / `moved` / `edited` / `retargeted`), then `removed`, `added`, `not_imported`; names of removed / not-imported slots are `"<slot> - <type name>"` (the importer's naming).
  `warnings` carries the template's own read warnings that 7.3 lists (`W_GUID_VERSION_MISMATCH`, `W_VERSION_MISMATCH`, `W_CHUNK_VERSION_UNEXPECTED`, `W_ZERO_RANGE_AXIS`), the plan's warnings, the writer's (`W_CMP_EXPANDED`, `W_FSM_STALE`, `W_TRAILER_KEPT`,
  `W_HASH_UNKNOWN`, `I_HASH_ZERO`) and always the three notes `I_BUDGET`, `I_PALETTE`, `I_UNVERIFIED` last (also on a refusal). `stats` keys: `occupied_before`, `occupied_after`, `capacity_bits`, `quota_changes`; on success also `mode`
  (`passthrough` / `patched` / `forced`), `end_bit`, `L`, `hash_flavour`.
* **What the glue must hand over**: `team` 0..8 (a stored `none` is handed over as 8; -1 is `E_TEAM_RANGE`), `color` -1 or 0..7, `physics` 0..3 (the unused 2 over a stored 2 is no change), `type_name` = the display name or empty with
  `type_id_hint` = the id (a model-less object), `cached_type` = the imported class (a different value is `E_CACHED_TYPE_CHANGED`), the unchanged pose parts exactly as imported (the glue already does this), `imported_slots` = every slot that imported.
  Adding any object needs `allow_unverified_rotation` (DEC-5.6) and a position inside `[min, max)` of every axis (never clamped); a tilted `up` (more than 1e-4 rad from +Z) is `E_TILT_UNSUPPORTED` with or without the gate.
* **Codes added beyond SPEC 7.3** (all in the spec table now and in `validate.MESSAGES`): `E_COLOR_RANGE` (colour not in -1..7 and not 8), `E_PHYSICS_RANGE`, `E_OPTION_INVALID`, `W_QUOTA_MAX_RAISED`. The `E_SHAPE_RANGE` pattern is for a dimension;
  a shape kind outside 0..3 has its own sentence (`validate.SHAPE_KIND_PATTERN`). Dimensions are named `radius` (shapes 1 and 2), `width`, `length`, `top`, `bottom`; only the dimensions the shape uses are checked.
* **Glue-produced codes** (`E_NO_TEMPLATE`, `E_TEMPLATE_CORRUPT`, `E_MIRRORED`, `E_ARRAY_NOT_EVALUATED`, `E_PATH_*`, `W_HIDDEN_EXPORTED`) are not made by the library; their texts are in `validate.MESSAGES` anyway and
  `TestGlueCodes` proves every one is a string constant of the glue / `io.py` sources, equal to the spec's pattern.

## 4. The new-object rules for the block star (as asked) and how they are met

* Cached type of a new object: learned from the template (unique class among objects of the same type, else of the same folder), else 0 **with `W_CACHED_TYPE_ASSUMED`** when its palette group (any ancestor) is `Structure` or `Scenery`
  (every palette path of the display name must be in such a group), else `E_CACHED_TYPE_UNKNOWN`. `Block, 1x1` on Breakneck: assumed 0 + the warning (the real file has no block; its Structure / Scenery objects are all class 0).
* Placement byte: the learned example (the **most common** `(placement, team, colour)` among the template's objects of the same `(folder, item)`, else of the same folder; the lowest slot breaks a tie), else `0x0C`; then the physics bits are
  replaced from the property when they differ from the example's. Fixed physics on a block with no example is `0x4C` (asserted on the real file: slots 610 to 614 are `0x4C`). Team: the example's raw value else 9 (neutral); colour: the example's else absent.
  A property that differs from the example's baseline is written for team / colour / physics and **refused (`E_FLAG_UNVERIFIED`) for symmetry, place-at-start, game-specific**; an unchanged property gives exactly the learned bytes.
* `flags2 = 1`, `in_bounds = 1`, `parent = 0`, label / spawn / shape / dims / extras from the object; the **lowest absent slots** (of the state after the deletions) in the order of the sorted names; the type must be in the map's stock table and its folder `< quota_count`
  (`E_OBJ_NAME_UNKNOWN`, `E_OBJ_NOT_STOCK`, `E_FOLDER_RANGE`; the Breakneck table lists ids whose folder is 82 or more, such as `Door` and `Wall (MCC)`: they cannot be added to this file).
* What the star script sends (`name "Star NNN"`, `slot None`, `type_name "Block, 1x1"`, forward (0, 1, 0) = yaw pi/2 = raw 12288, `physics 1`, ...) is exactly what the real-file tests send (with forward (1, 0, 0) = raw 8192); both work.

## 5. Decisions taken in G5 (most reasonable choice made, work continued)

1. **Free slots are the absent slots of the state after the deletions** (a slot vacated in the same export can be reused). SPEC 5.6 says "lowest absent slot index" without saying which state. Pinned by `test_slots_vacated_by_a_deletion_are_free_for_new_objects`.
2. **Learned example** = most common triple, lowest slot on a tie, exact `(folder, item)` first and then the folder (the task text said "same folder if any", SPEC 5.6 says "same (folder, item)": both, in that order). Pinned in `TestLearning`.
3. **`hash_policy` that differs from the template's recipe counts as a modification**: a clean template is then re-hashed (only the 20 SHA-1 bytes change; `stats['mode'] == 'forced'`); the template's own recipe on a clean template is a passthrough. The 6.4 contract note lists three
   conditions for "data == template"; a forced recipe is a fourth, because the Blender option "Hash (advanced)" would otherwise do nothing on an unedited map.
4. **`fsm_policy = DROP` on a `cmp4+fsm` template** yields `cmp4` (the unmodified wrapper bytes are kept, SPEC 2.8 "after edits to other blocks"), not a plain file.
5. **A valid claimant of a slot that is not in `imported_slots` is honoured** (its edits are applied; no `W_SLOT_NOT_IMPORTED` for it).
6. **`W_CACHED_TYPE_ASSUMED` and `E_CACHED_TYPE_UNKNOWN` are reported once per type name**, not once per object (34 blocks give one warning); every other per-object code is per object.
7. **Orientation**: an unchanged pose (both vectors within `ANG_TOL = 1e-4` rad) keeps its raw bits; a changed or new one needs `up` within 1e-4 of +Z and a forward with a horizontal part, else `E_TILT_UNSUPPORTED` (reported instead of, not together with, `E_ROTATION_GATED`);
   then the gate; the yaw is `atan2(forward.y, forward.x)`.
8. **Raw physics 2 counts as normal** when comparing with the Blender value (SPEC 4.9) and is written as 0 if the physics changes.
9. **Retarget**: a new type whose class cannot be learned (and is not in an assumed group) is `E_RETARGET_CLASS`, like a differing class (SPEC 5.3 only names the differing case).
10. **`E_TYPE19_UNDETERMINED` is reachable only through `ExportObject.cached_type == 19` on a new object whose class cannot be learned** while the template has no type-19 object (an undetermined file has none to learn from or edit). The guard for an existing class-19 object is unit tested directly.
11. **`E_OTHER_RANGE` is checked once the class is known** (per slot / per new object), not in step 3; for a class without extras both values must be 0 ("must be 0 to 0"); class 19 accepts -1 (none).
12. **Verification compares a forced re-encode of the output with the output only for a template that a forced re-encode reproduces** (a wrong `_eof` value or `chdr` length is kept verbatim by a patched save and repaired by a forced one: `TestTemplatesThatAreNotCanonical`).
13. **Tier 1 type rule** (7.4): a name equal to the template's own `"Unknown (0x....)"` string, or an empty name with the matching id, keeps the bits; the stock check still applies (error, or `W_UNKNOWN_TYPE_KEPT` with the option; `0xFFFF` is shown for an object with no type). For a non-stock **map** the per-object type checks are skipped.
14. **Test layout**: U-10 write parts are in `test_container_write.py` (the read parts stay in `test_container_variants.py`); U-16 for `reencode_mvar` is `test_reencode_cli.py`.
